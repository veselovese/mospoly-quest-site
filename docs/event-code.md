# Код мероприятия — задача A25

Сайт открывается с ввода кода мероприятия. Код состоит из цифр (4–8 знаков) и задаётся организатором
в админке вместе с квестом. По коду открывается квест мероприятия, а рейтинг строится отдельно для каждого
мероприятия: `/leaderboard?id=6479`.

Бэкенд (задача A23, Гертнер и Коваленко) на момент написания в работе, поэтому ниже — **предлагаемый контракт**,
по которому сделан фронтенд и мок (`src/api/mock.js`). Если на бэке сделано иначе, править нужно
`src/api/client.js` (функции `getEvent`, `registerParticipant`, `getEventRanking`) и мок.

## Контракт API

### `GET /api/events/{code}/` — без авторизации

```json
{
  "code": "6479",
  "title": "День открытых дверей",
  "is_active": true,
  "quest": {
    "key": "zoo",
    "title": "Код манула",
    "brand_label": "Московский зоопарк · лаборатория генетики",
    "welcome_lead": "...",
    "welcome_text": "...",
    "duration_text": "20–30 минут",
    "task_count": 7
  }
}
```

- `quest` — та же публичная конфигурация квеста, что раньше отдавал `GET /api/quest-config/`.
  Фронтенд выбирает интерфейс по `quest.key` (`zoo`, `orlov`).
- Кода нет → `404`.
- Закрытое мероприятие (`is_active: false`) тоже отдаётся: по нему можно открыть рейтинг,
  но экран входа покажет «Мероприятие завершено, регистрация закрыта». Ответ `403` с `detail` тоже понимается.

### `POST /api/participants/` — регистрация на мероприятии

Тело: `{"first_name": "...", "last_name": "...", "event_code": "6479"}`.
Ответ — как раньше, плюс `event_code`; `quest` — квест мероприятия. Неизвестный код → `404`,
закрытое мероприятие → `403`.

### `GET /api/events/{code}/ranking/` — рейтинг мероприятия, без авторизации

Строки в прежнем формате: `[{place, first_name, last_name, score, solved_tasks, attempts_count, time_seconds}]`.
Только участники этого мероприятия, сортировка прежняя. Неизвестный код → `404`.

`GET /api/quest-config/` и `GET /api/ranking/` фронтенд больше не вызывает.

## Поток на фронтенде

1. Есть итоги завершённой смены для сохранённого мероприятия → экран итогов
   (кнопки «Найди себя на лидерборде» и «Ввести другой код мероприятия»).
2. Идёт смена → квест. В боковой панели — «Мероприятие {код}», ссылка на рейтинг мероприятия.
3. Мероприятие не выбрано → экран кода (`EventCodeScreen`).
4. Мероприятие выбрано → экран входа с плашкой «Мероприятие {код} · {название}» и ссылкой «Сменить код».

- `/?id=6479` — ссылка для QR-кода: код подставляется и проверяется без ручного ввода.
- Выбранное мероприятие хранится в localStorage (`quest-event:v1`, без токенов) и при открытии
  проверяется заново. Если код удалён или мероприятие закрыто — выбор сбрасывается с пояснением.
  Без сети используется сохранённое.
- Барьер повторного прохождения (`docs/prevent-repeat-quest.md`) ставится на пару «квест + мероприятие»:
  ключ `quest-completion:v1:<квест>@<код>`. На другом мероприятии с того же устройства участвовать можно.
- `/leaderboard` без `id` — форма кода; `?id=` — рейтинг мероприятия с обновлением раз в 3 с.
  Неизвестный код возвращает к форме с ошибкой.

## Мок (`npm run dev:mock`)

| Код | Мероприятие | Квест |
|---|---|---|
| `6479` | Демо: Московский зоопарк | `zoo` |
| `1234` | Демо: расследование Орлова | `orlov` |
| `0000` | Прошедшее мероприятие (закрыто) | `zoo` |
