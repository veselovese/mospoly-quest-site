# Списание баллов за подсказки (#24)

## Контракт Django backend

`GET /api/tasks/` дополнительно возвращает для каждого задания:

```json
{
  "hint_penalty": {"points_per_hint": 1, "max_hints": 3},
  "hints_used": 0,
  "available_points": 10
}
```

Без валидной `hint_penalty` открытие новых подсказок отключено с объяснением, что организатор ещё не включил функцию. Текст не раскрывается бесплатно при ошибке API. Это позволяет безопасно отклонить запрос к старому backend, но выпуск frontend должен следовать за обновлением backend.

`POST /api/tasks/{task_id}/hints/`, авторизация `Token`, тело `{"hint_index": 1}` (индекс с 1) возвращает `{"hints_used": 1, "available_points": 9}`. Клиент открывает текст только после подтверждения. Повтор одного индекса идемпотентен: нужен для безопасного восстановления после потери ответа. Нельзя запросить индекс больше следующего, чужое/неактивное/решённое задание, открыть подсказку после завершения. Для этих ситуаций нужны 400/404/409, для отсутствующего токена 401.

Бэкенд транзакционно фиксирует уникальные подсказки участника/задания и штраф каждой записи, награда равна `max(0, task.points - sum(сохранённых штрафов))`. Изменение настройки не меняет стоимость ранее открытых подсказок. `attempts/`, итог и рейтинг должны использовать эти сохранённые баллы; клиент не передаёт доверенное число баллов. Параллельные подсказка/ответ должны быть сериализованы на сервере. GET tasks восстанавливает число использованных подсказок.

Тексты подсказок по-прежнему являются частью клиентского сценария и доступны через исходники. Эта задача учитывает обычное открытие подсказок в UI и не является защитой от исследования DevTools. Для строгой защиты сам текст должен выдаваться исключительно сервером.
