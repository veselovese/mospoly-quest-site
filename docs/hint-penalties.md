# Списание баллов за подсказки (#24)

## Статус

Клиентская часть и mock API подготовлены. Настоящий Django backend находится отдельно: `LineAhpe/mospoly-quest-backend`. На 25.10.2026 чтение через подключённый GitHub возвращает 404; исходники и развёрнутый API не проверены. Этот PR нельзя считать законченной серверной реализацией или включать без согласования контракта.

Требование Матвея Веселова от 21.10.2026: незначительно уменьшать баллы за задание при подсказке. Размер штрафа не задан. В моке используется **1 балл за каждую новую подсказку**, минимум 0 за задание; это демонстрационная настройка, не утверждённое преподавателем число. Рабочий клиент получает размер штрафа с сервера.

## Предлагаемый контракт для backend

`GET /api/tasks/` дополнительно возвращает для каждого задания:

```json
{
  "hint_penalty": {"points_per_hint": 1, "max_hints": 3},
  "hints_used": 0,
  "available_points": 10
}
```

Без валидной `hint_penalty` открытие новых подсказок отключено с объяснением, что организатор ещё не включил функцию. Текст не раскрывается бесплатно при ошибке API. Это намеренное поведение, поэтому PR оставлен черновиком до серверной интеграции.

`POST /api/tasks/{task_id}/hints/`, авторизация `Token`, тело `{"hint_index": 1}` (индекс с 1) возвращает `{"hints_used": 1, "available_points": 9}`. Клиент открывает текст только после подтверждения. Повтор одного индекса идемпотентен: нужен для безопасного восстановления после потери ответа. Нельзя запросить индекс больше следующего, чужое/неактивное/решённое задание, открыть подсказку после завершения. Для этих ситуаций нужны 400/404/409, для отсутствующего токена 401.

Бэкенд должен транзакционно фиксировать уникальные подсказки участника/задания и рассчитывать `max(0, task.points - hints_used * points_per_hint)`. `attempts/`, итог и рейтинг должны использовать эти сохранённые баллы; клиент не передаёт доверенное число баллов. Параллельные подсказка/ответ должны быть сериализованы на сервере. GET tasks восстанавливает число использованных подсказок.

Тексты подсказок по-прежнему являются частью клиентского сценария и доступны через исходники. Эта задача учитывает обычное открытие подсказок в UI и не является защитой от исследования DevTools. Для строгой защиты сам текст должен выдаваться исключительно сервером.
