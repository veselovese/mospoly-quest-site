# Локальный запрет повторного прохождения — задача №27

После успешного `POST /api/participants/finish/` (полный финал или досрочное завершение)
фронтенд сохраняет итоги отдельно от прогресса, под ключом `quest-completion:v1:<questKey>`.
`clear()` удаляет активную сессию, сохраняя этот маркер. Токен в маркер не записывается.
При следующем открытии показываются имя/ник участника, итоги и ссылка на рейтинг, без кнопки новой смены.
Ошибка завершения не блокирует участника: можно повторить запрос или продолжить квест.
Начатая, но ещё не завершённая сессия восстанавливается как раньше.
Сохранённые завершённые сессии версии 2 также создают маркер при загрузке.
Завершение в одной вкладке закрывает прохождение в другой через событие `storage`.
Разные ключи квестов (`zoo`, `orlov`) имеют разные маркеры.

## Граница реализации

Это клиентский барьер, а не доказательство личности. Очистка данных браузера, другой профиль,
инкогнито или другое устройство обходят его. Если localStorage недоступен, барьер живёт только
в памяти вкладки. На общем компьютере маркер затронет следующих участников того же квеста.
Ключ события/мероприятия пока отсутствует в API: новое мероприятие с тем же `questKey` также
попадёт под прежний маркер. Управляемый сброс организатором требует серверной поддержки.

Для полного запрета сервер должен идентифицировать участника/команду и мероприятие,
атомарно ограничивать регистрацию по этой паре, возвращать существующую активную сессию,
а после завершения отклонять новые регистрации и попытки. Совпадение имени/ника не является
идентификатором. Репозиторий бэкенда в эту задачу не входит; текущий API не изменён.

Проверка хранилища: `node --test tests/completionStore.test.js`.
В браузере: продолжение после обновления, отказ сервера завершения, успешный отказ/полный финал,
повторное открытие, вторая вкладка, отдельный ключ другого квеста и ссылка на рейтинг.
